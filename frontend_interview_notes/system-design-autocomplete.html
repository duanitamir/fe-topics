Case Study: Reusable Autocomplete

Design a reusable imported component from UI behavior to package exports: framework-independent logic, accessible interactions, asynchronous data, and explicit tradeoffs.

Step 1 · Understand the reusable component

Prompt: Design an importable, single-select autocomplete for users, products, or locations. Consumers supply item identity, labels, data access, and rendering. The package owns a predictable accessible interaction contract; it does not own the host application’s domain model or backend.

ArchitectureAccessibility

Functional requirements

  • Type a query, see suggestions, navigate enabled options with keyboard/pointer, select an item, clear the value, and dismiss the popup.
  • Support local in-memory suggestions and asynchronous remote sources through the same data-source interface.
  • Expose distinct input text, selected item, open state, and highlighted option; provide controlled and uncontrolled ownership modes with clear change reasons.
  • Represent loading, empty, failed, disabled, and retry states. Preserve correct behavior during rapid input, IME composition, and out-of-order responses.
  • Provide a headless core, a React adapter, optional default UI/styles, and supported customization without deep internal imports.

Non-functional requirements

  • Accessibility: Follow the editable combobox/listbox interaction pattern with meaningful names and correct focus/active-option behavior; verify browser/screen-reader combinations.
  • Responsiveness: Keep keystroke rendering immediate; choose an illustrative 200 ms debounce for remote queries and render a bounded result set (for example 20). Measure typing/interaction latency separately from network latency.
  • Correctness: The newest eligible query/context owns the displayed results; one user selection yields one semantic onValueChange notification.
  • Packaging: Side-effect-safe imports, explicit exports, types, peer React dependency in the adapter, SSR-safe initialization, and disposal of timers/requests/listeners.
  • Isolation: No global shared personalized cache, router dependency, Redux/XState requirement, or hard-coded authentication/API URL.

In scope and out of scope

In scope: A framework-independent TypeScript controller and optional React integration, asynchronous orchestration, single selection, headless slots, default non-portaled results, and small bounded lists. Form integration happens through adapters.

Out of scope: Multi-select, arbitrary free-text creation, a search-engine backend, infinite results, a universal design system, and complete bindings for every framework. Portals, virtualization, grouped options, and other adapters are explicit extensions with additional accessibility contracts.

Validate ambiguity: “Agnostic” means domain/data/presentation independence and a framework-independent core; the React adapter itself requires React. It does not promise that the same React component can be imported into Vue unchanged. Follow the four-step interview framework.

UI sketch: query, active option & feedback

Sketch the visible contract before the implementation. Input text is not the selected item, and keyboard highlight is not selection. The following is a static design wireframe, not a live autocomplete.

Step 2 · Blueprint and dependency boundaries

Separate domain adapters, interaction state, framework integration, and presentation. A UI framework or an API client should be replaceable without rewriting selection semantics.

ArchitectureDesign patternReact

Start simple: Use a reducer/controller plus a scoped instance. Native React Context can distribute that stable instance among compound subcomponents; the subscription mechanism reads its snapshots. A custom hook alone does not make separate callers share an owner.

Alternative: A React-only useReducer hook is simpler if framework independence is not a real requirement. An established accessible combobox library may reduce risk further; justify a custom package only when requirements or integration constraints warrant it. See headless composition and state-tool comparisons.

Public API: types, identity & ownership

Expose a small typed contract. The following is a proposed API sketch, not an installed package. It separates optional controlled/default pairs and treats asynchronous loading as an injected dependency.

TypeScriptState management
export type DataSource<T> = (
  query: string,
  context: { signal: AbortSignal }
) => Promise<readonly T[]>;

type Owned<T, Name extends string> =
  | { mode: 'controlled'; value: T; onChange: (value: T, reason: Name) => void }
  | { mode: 'uncontrolled'; defaultValue?: T; onChange?: (value: T, reason: Name) => void };

export type AutocompleteConfig<T> = {
  dataSource: DataSource<T>;
  getItemKey: (item: T) => string;
  getItemLabel: (item: T) => string;
  isItemDisabled?: (item: T) => boolean;
  query: Owned<string, 'input' | 'select' | 'clear'>;
  selection: Owned<T | null, 'select' | 'clear' | 'input'>;
  // Changes in permissions, tenant, locale or source semantics invalidate requests.
  dataScopeKey: string;
  minQueryLength?: number;
  debounceMs?: number;
};

Semantics: Controlled values are authoritative host inputs; a change request is not committed until the owner supplies the new value. Default values initialize an uncontrolled owner and are not a synchronization channel. Validate/warn against changing ownership modes after mount; do not call change callbacks solely because a controlled prop was echoed back.

Separate facts: Query text, selected item identity, and active option key have different lifetimes. Stable keys survive result replacement/reordering; labels need not be unique. If an item’s shape changes remotely, preserve identity while defining how its latest label is resolved. Do not compare whole items only by object reference.

API surface: Expose open state similarly if required; keep active option internal initially. Return semantic reason codes rather than leaking the internal event format. A simpler single-select product can expose fewer ownership knobs; a large generic API increases invalid combinations and test scope.

Type boundary: Generic T preserves relationships between items and callbacks but does not validate remote JSON. The host data adapter validates results and permissions; see reusable React typing and controlled contracts.

Step 3 · State and transition model

Use a small explicit transition model before introducing a statechart library. Keep synchronous transitions pure, with timers/network work owned by the coordinator.

State managementDesign pattern
Event / transitionRuleFailure avoided
Input changedUpdate query; clear committed selection under this case’s policy; reset active option; invalidate older requests.A selected identity remaining after the user has changed its displayed text.
Request started / resolved / rejectedAttach request generation + scope; apply only if current and still eligible.A slow old query overwriting a newer result.

Escape / outside dismissalClose without changing confirmed value; invalidate work that must not reopen results.A late response reopening a dismissed popup.

State shape: Store canonical keys and small status unions, derive visible/selected flags, and keep immutable snapshots stable while nothing changed. A finite listbox usually does not need a global Redux store. XState earns consideration for significantly richer parallel/loading/creation workflows; Context only distributes the chosen owner. See same-problem alternatives.

Async search: debounce, cancellation & stale-result guards

The hard guarantee is latest eligible request wins, not simply “we debounce fetch.” The request key must include the data scope as well as the query.

ConcurrencyAPI integrationPerformance
MechanismPurposeLimit
DebounceDelay remote work until rapid input pauses.It reduces request count but does not stop earlier requests completing out of order.
AbortControllerCancel obsolete work supported by the data source.Cancellation may arrive too late or be ignored; it does not guarantee server cancellation.
Generation + scope checkIgnore completion from an obsolete query, account, locale, source, or disposed instance.Use it even when abort exists; ensure close/clear invalidates relevant generations.
Min length + bounded result countAvoid expensive broad requests and excessive rendering.The API still needs server-enforced limits.
Cache / request deduplicationReuse equivalent results or in-flight work through a host policy.A single instance must not abort shared work that other consumers still need.

Sequence example: Query “a” starts generation 1; “al” starts generation 2 and aborts 1. If generation 1 still resolves last, its result is ignored. If the user closes the popup before 2 resolves, the result must not reopen it. If tenant/account changes, old results are invalid even if the string remains “al.”

IME composition: Update visible text while composition is active, but defer search/selection shortcuts until compositionend under the documented policy. Enter may confirm composed text rather than select a result; check isComposing and verify real browser behavior.

Normalization: Local filtering can be injected; do not lowercase/remove accents unconditionally if locale/domain semantics differ. Remote ranking belongs to the data source. Choose a minimum-length and empty-query policy with the host rather than embedding a product assumption.

Related: cancellation, stale completion, and frequency control.

Accessibility: combobox/listbox as a contract

Use the editable combobox with listbox popup pattern for this case. Accessibility comes from consistent roles, relationships, state, focus, and interaction—not from adding aria labels after implementation.

AccessibilityBrowser
Element / interactionRequired contract
InputAn accessible label; role=combobox; aria-expanded reflects popup visibility; aria-controls refers to the related listbox when applicable; aria-autocomplete=list for suggestions.
Popup and itemsrole=listbox and role=option; stable DOM IDs; aria-selected follows the documented committed-selection model; aria-disabled for disabled options.
Active optionDOM focus remains on input; aria-activedescendant refers only to the currently mounted active option. Selection and highlight remain distinct.
KeyboardArrow keys navigate/open as defined, Enter commits an enabled active option, Escape dismisses, Tab preserves normal focus flow. Do not hijack native text-editing shortcuts.
PointerKeep the intended option interaction alive across input blur; avoid duplicate selection and avoid indiscriminately preventing focus on touch/scroll.
Async feedbackUse a polite status for useful loading/results/error changes, not a live announcement for each keystroke. Keep interactive retry controls out of the option model.

ID ownership: Generate per-instance IDs in the adapter using an SSR-compatible mechanism such as React useId. Keep item-key → option-ID mapping stable; do not concatenate untrusted keys into selectors/markup without appropriate handling.

Virtualization extension: aria-activedescendant cannot reference an unmounted item. Scroll/mount before exposing it, and test list-size/position metadata and screen-reader behavior. For 20 results, a normal list is usually simpler and more robust.

Verification: Test keyboard, touch, zoom, IME, disabled items, empty/error states, and target screen-reader/browser combinations against the current WAI-ARIA Authoring Practices. Start from an established accessible primitive when custom behavior is not essential. See focus ownership and component accessibility contracts.

Presentation and host adapters: imported, not embedded

Offer supported exports for a headless hook/compound API and an optional styled convenience component. Both share the same interaction owner; slots change presentation without duplicating behavioral logic.

ReactDesign patternForms
// Proposed consumer API; implementation belongs to the package in this case study.
import { Autocomplete } from '@acme/autocomplete/react';
import '@acme/autocomplete/styles.css';

type Person = { id: string; displayName: string };
const loadPeople = async (query: string, { signal }: { signal: AbortSignal }) => {
  const response = await fetch(`/api/people?q=${encodeURIComponent(query)}`, { signal });
  if (!response.ok) throw new Error('Could not load people');
  return response.json() as Promise<Person[]>; // Host validates real JSON at this boundary.
};

export function PersonPicker({ accountScope }: { accountScope: string }) {
  return <Autocomplete<Person>
    dataSource={loadPeople}
    dataScopeKey={accountScope}
    getItemKey={person => person.id}
    getItemLabel={person => person.displayName}
    query={{ mode: 'uncontrolled', defaultValue: '' }}
    selection={{ mode: 'uncontrolled', defaultValue: null }}
    label="Choose a person"
    renderOption={person => <span>{person.displayName}</span>}
  />;
}

Adapter API: The convenience component extends the core configuration with label, renderOption, and optional presentation props. Those React-specific types live only in the React entry point; core types remain framework-independent.

Slots/bindings: A headless variant can expose Input, Results, Option, and Status or prop-getter functions. Merge required IDs/roles/event handlers predictably; preserve caller refs and document which handlers may prevent library behavior. A renderOption customizes option content, not arbitrary nested buttons or replacement focus semantics.

Form adapter: Submit the selected item’s domain key in a hidden/native field or integrate with the host form library’s field API. Pass validation error, required, disabled, blur/touched, reset, and focus behavior intentionally. Input text is not proof that a valid item was selected.

Tradeoffs: One highly polymorphic component can become harder to type and use than a focused default plus a headless API. Avoid hidden dependencies on a router, theme provider, global store, or fetch wrapper. See compound slots and adapters.

Directory structure: core, adapters & public exports

Organize by ownership boundaries, not a generic utils folder. This is an illustrative source layout for the proposed component package; these files describe the design and are not a claim that an implementation has been added to this documentation repository.

ArchitectureTooling

Why this split: Pure transitions are easy to verify independently. The coordinator owns asynchronous resources, while React owns mounting/subscription/DOM relationships. Stable domain-facing adapters prevent examples from becoming hard-coded production dependencies.

Packaging, SSR & compatibility

An importable component includes a distribution contract, not just a source file. Document supported runtime/framework versions, exports, CSS behavior, and semantic-versioning rules.

ToolingReactResource lifecycle
{
  "name": "@acme/autocomplete",
  "type": "module",
  "exports": {
    "./core": { "types": "./dist/core/index.d.ts", "import": "./dist/core/index.js" },
    "./react": { "types": "./dist/react/index.d.ts", "import": "./dist/react/index.js" },
    "./styles.css": "./dist/styles.css"
  },
  "files": ["dist"],
  "sideEffects": ["**/*.css"],
  "peerDependencies": { "react": "^18.0.0 || ^19.0.0" },
  "peerDependenciesMeta": { "react": { "optional": true } }
}

Interpretation: This illustrative ESM-only export map assumes the build emits exactly these files. Mark React optional so core-only consumers need not install it; React-adapter consumers must install a supported version. Externalize React from the bundle to avoid duplicate runtimes. Include declaration files and opt-in CSS; exclude examples/test infrastructure from the published artifact.

Build pipeline: Type-check, test, emit JS/declarations, copy CSS, and verify imports from a packed tarball in consumer fixtures. ESM-only is simpler; add a documented CommonJS build only for an actual support requirement, then verify conditional exports and module identity. Do not deep-import unexported source paths.

SSR: Core imports must not touch window/document; create browser resources after the adapter is mounted. Provide a stable initial/server snapshot to useSyncExternalStore and stable hydration IDs. For server/client frameworks, expose the React interactive boundary appropriately without marking the whole core client-only.

Lifetime: Strict Mode setup/cleanup replay must not leak a controller, timer, subscription, or request. Never start network work at module import or perform it inside a pure reducer. Behavior changes to keyboard handling or callback reasons can be breaking changes even if TypeScript still compiles. See module boundaries and snapshot contracts.

Performance, caching & fallback decisions

Optimize the path that is actually slow: typing/rendering, local matching, network suggestions, or list layout. The package cannot guarantee the host search service’s scale or ranking latency.

PerformanceSecurityResilience
PressureChoiceTradeoff
Remote requests on each keyDebounce eligible queries; cancel/ignore obsolete work.Adds intentional response delay; do not debounce the visible input value.
Repeated equivalent searchesLet a host cache own keys, TTL, in-flight reuse and account scope.Library-global caches can leak personalized data; shared cancellation needs independent ownership.
Large local collectionPre-index/filter outside render or use a worker when measured CPU cost justifies it.Worker messaging/index lifecycle adds complexity; a remote source or smaller result set may be simpler.
Many visible optionsBound result count first; virtualize only with the accessibility contract intact.Virtualization complicates active-descendant IDs, scrolling, and screen-reader behavior.
Remote source failsRetain typed query, expose error/retry, optionally show clearly scoped cached results.Stale results may be useful but permissions/selection must still be validated server-side.
Rich custom contentKeep render callbacks pure and render safe React content.Do not accept raw unsanitized HTML; expensive option markup needs profiling.

Monitoring: Optional host callbacks can report request duration, safe failure codes, stale completions discarded, selection completion, and keyboard journey failures. Do not emit raw queries or option content by default: they can contain personal/sensitive data. Use bounded metric labels and a host-provided telemetry sink instead of a mandatory analytics SDK.

Security boundary: Even an authorized cached suggestion is not permanent authorization to submit that item. Revalidate on the server. Avoid public/CDN caching of personalized suggestions unless cache/auth contracts explicitly permit it; see cache placement.

Verification: test interactions, races and the packed artifact

Test the reusable contract at its boundaries. A reducer snapshot alone cannot establish browser focus behavior, accessible interactions, or package compatibility.

AccessibilityConcurrencyTooling
LayerCritical cases
Pure transitionsDisabled/all-disabled/empty results; selection versus highlight; clear/reset; changing ownership mode; same label with different keys; active key removed.
Async coordinatorSlow A after fast B; ignored abort; close while loading; account/source changes; retry; disposal; debounce timers; shared-cache cancellation.

Fallback criteria: A library failure must not submit an unintended value, trap focus, or silently replace results from the wrong account. Document unsupported combinations rather than advertising a universal solution. Use examples as compatibility fixtures, not only marketing demos.

Step 4 · Wrap up and defend the tradeoffs

Recap: A per-instance TypeScript controller owns transitions; a coordinator owns async work; the React adapter binds the combobox contract; host adapters own domain data, authentication, caching, and form integration. Public subpath exports make these boundaries importable.

ArchitectureDesign pattern
AlternativeChoose whenWhy not always
Native datalistA small native suggestion list meets interaction and presentation requirements.Customization, async states, consistent keyboard/display behavior, and rich options are limited.
Existing accessible combobox primitiveIts behavior and customization model fit the product.Audit support/license/bundle/API requirements; avoid writing a custom control merely for uniqueness.
React-only hook/componentOnly React consumers exist and framework independence adds no real value.A future framework adapter would need extraction, but premature abstraction also has cost.
Framework-independent core + adaptersMultiple host frameworks/products need the same behavior and data contract.More public APIs, adapter tests, versioning and lifecycle integration to maintain.
Reducer/controller vs XStateSmall transitions favor a reducer; complex hierarchical/parallel actor workflows can favor XState.A machine library is not required to implement a valid FSM; Context/Redux solve different ownership/subscription concerns.
